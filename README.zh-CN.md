# Three.js FPS 模板

一个功能完整、开箱即用的第一/第三人称射击游戏模板，基于 **Three.js + TypeScript + Vite**。

项目内置了**三张地图**——完整的靶场关卡；一条赛车跑道，其车库中停着三台细节丰富、**都能开**的载具；
以及一个模型测试场景，用来完整展示业界是怎么做一个 PBR 资产的——
外加**十把手感各异的枪械**、**手雷 / 烟雾弹 / 闪光弹**、第一与第三人称双视角、程序化生成的枪械模型、
带 IK 的程序化角色动画、对象池化的特效系统，以及一套完全合成的音频引擎——**且不含任何二进制资源文件**。
所有贴图、模型、音效都在运行时生成，因此仓库克隆下来即可运行，也能完全离线工作。

## 快速开始

```bash
npm install
npm run dev      # 打开 http://localhost:5173
```

```bash
npm run build    # 类型检查 + 生产构建到 dist/
npm run preview  # 预览生产构建
npm run typecheck
```

需要 Node 20.19+ / 22.12+。

## 功能一览

### 角色与移动
- Quake 风格的加速度模型（地面/空中加速度分离，独立的摩擦力步骤），手感干脆跟手。
- 土狼时间、跳跃缓冲、自动上台阶（可直接走上矮台与楼梯）。
- 姿态系统：站立、蹲下（按住或切换）、以及冲刺时下蹲触发的保留动量的滑铲。
- 体力限制的冲刺、坠落伤害、落地硬直。
- 区分地面材质的脚步声、视角摇晃（head bob）、横移倾斜、落地下沉、基于 trauma 的镜头震动。

### 摄像机
- **第一人称**：手部模型（view model）放在独立场景中渲染，叠加时清空深度缓冲——枪永远不会穿墙，
  并且使用独立的更窄 FOV，因此在大视场角下枪械也不会变形。
- **第三人称**：过肩镜头臂，遇到遮挡自动收近，瞄准时向肩部收紧。
- 后坐力被合并进"权威瞄准角"，因此子弹永远沿着玩家看到的方向飞行；
  纯表现层的运动（摇晃、震动、倾斜）不会影响弹着点。

### 武器
十把武器，各自拥有独立的手感、后坐力特征、音色和换弹方式：

| 槽位 | 武器 | 说明 |
| --- | --- | --- |
| 1 | M9 Sidearm | 半自动手枪，出枪快，后坐力柔和 |
| 2 | TMP-18 Machine Pistol | 1200 RPM 全自动手枪，20 发弹匣，散布扩张极快 |
| 3 | Model 29 Magnum | 六发左轮，手炮级伤害，后坐力凶猛 |
| 4 | MP-9 Vector | 950 RPM 冲锋枪，全自动/半自动，后坐力低，射程差 |
| 5 | AR-15 Carbine | 全自动/三连发/半自动，红点瞄具，有可背板的固定弹道 |
| 6 | SR-25 Marksman | 带镜半自动精确射手步枪，20 发，可穿透掩体 |
| 7 | M40 Marksman | 栓动狙击枪，带密位分划的瞄准镜，一枪致命 |
| 8 | M249 Support | 弹链供弹 100 发轻机枪，火力压制，换弹长达六秒 |
| 9 | M870 Breacher | 泵动霰弹枪，9 颗弹丸，逐发压弹（可中途打断直接开火） |
| 0 | AA-12 Sweeper | 弹鼓供弹的全自动霰弹枪 |

背后的系统：
- 射线判定弹道，包含每把枪独立的伤害衰减、命中部位（头/躯干/四肢），以及 **材质穿透**——
  步枪和狙击枪可以打穿 2 号靶道的胶合板墙，击中后面的钢靶。
- 散布模型综合了基础锥角、移动、腾空、下蹲以及每发累积的扩散；子弹用高斯采样，霰弹用"环形 + 抖动"分布。
- 后坐力支持固定弹道脚本（步枪与冲锋枪各有一套），弹道用尽后转为带爬升的随机后坐力，
  并有一部分"不可自动回正"的量需要玩家手动压枪。
- 射击模式切换、松开扳机后仍会打完的三连发、栓/泵动作的循环锁定、战术换弹与空仓换弹区分、
  空枪击发、出枪/收枪、武器检视。

### 投掷物
三种投掷物共用同一个投掷键，投出的是会与场景碰撞弹跳的物理抛射体：

- **M67 手雷**——三秒引信，按住投掷键即开始"煮引信"（拔销即开始计时），握太久会在手里炸开。
  伤害按距离衰减，并且需要通视，所以掩体是真的能挡住的。
- **M18 烟雾弹**——引信到点后释放，持续二十秒不断喷出粒子，形成足以藏身的烟幕。
- **M84 闪光弹**——致盲强度同时取决于距离、是否通视、以及你当时有没有看向它；
  同时会真的"震聋"你：整条音频链路被低通滤波压下去，并叠加一段耳鸣。

轻按 `G` 是过肩投掷；同时按住 `鼠标右键` 则是低手轻抛，适合把弹丢进掩体后面。

### 特效
- 枪口火焰（手部模型与世界空间两套，互不重复）、动态枪口光源、飞行曳光弹、带弹跳物理与落地音效的抛壳。
- 区分材质的弹着效果：火花、扬尘、烟雾、碎块，每种表面独立调参。
- 贴合命中表面朝向的弹孔贴花，池化管理并带淡出回收。
- 爆炸：火球、破片、翻滚的烟尘、地面碎屑、向外扩散的冲击波环，以及亮到能把整个射击棚重新照亮的爆闪光源。
- 单次 draw call 的 GPU 粒子系统（CPU 模拟、空闲链表池化），用于火花与烟雾。

### 音频
所有音效都由 WebAudio API 在运行时合成——枪声（噪声爆裂 + 低频扫频 + 中频冲击 + 混响回声）、
机械动作声、换弹分步音、脚步声、按材质区分的弹着声、钢靶回响、抛壳落地、命中提示与 UI 音效。
声音带有手动的距离衰减、立体声声像和随距离变化的空气吸收，并设有发声数上限，
保证全自动连射时也不会把音频图压垮。

### 地图

三张地图都继承自 `LevelBuilder`，共用同一套辅助函数（`box`、`prop`、`sign`、`pedestalRow`、
`buildDustField`、`buildSkyAndSun`），并且可以在运行时用 `M` 键或菜单随时切换。切换时会拆掉碰撞世界、
计分会话和关卡持有的全部 GPU 资源再重建；玩家、武器和 HUD 只是重新指向新关卡。

### 靶场
- 五条靶道：近距离钢靶道、手枪/冲锋枪渐进道（含穿透演示）、中央精度道（有直通 100 米铜锣的通路）、
  移动靶道、以及远至 150 米的远距离道。
- 六种靶标：10 环计分的纸质靶、**能吃伤害、被打倒后在重力作用下向后翻倒、过一会再弹起复位的人形靶**、
  可摆动的钢板靶、翻倒靶、导轨移动靶、远距离铜锣。
- 十个武器展示台、弹药补给箱、距离标识牌、掩体道具、有顶棚的射击线。
- 计分、实时命中率，以及带本地最佳成绩记录的计时挑战（`K` 键）。

### 赛道

- 整条封闭赛道由**一条样条曲线**生成。采样一次、再沿法线横向偏移，就能得到这张图需要的所有条带：
  沥青路面、白色边线、砂石缓冲区、护栏和防护网——所以赛道布局只定义在一个地方。
- 路肩**只铺在真正在转弯的地方**：每个弯的内侧都有，急弯则内外两侧都有；高速弯外侧还堆了轮胎墙。
- 起终点方格线、交错排布的发车格、带五灯循环发车序列的龙门架、刹车点提示牌、旗手岗、赞助商围板、
  12 排看台和计时塔。
- 维修区：格纹维修墙、计时台、划线的维修位、成套轮胎、加油机和气动扳手；后方是拖车与集装箱构成的围场，
  以及泛光灯塔。
- 一座三车位的车库停放三台载具，内有工作台、工具柜、洞洞板、轮胎架、千斤顶、支撑架、油桶、气管盘，
  后墙一排武器展示台。
- 维修区东侧还有一条勤务道靶场——射击台、五条靶道、距离标识和挡弹土堤——让计分、计时挑战和每一把枪
  在这张图上依然有的放矢。

### 雷神机甲

`src/world/Thor.ts` 造了一台星际争霸 2 风格的人族重型突击机甲，**可以进去开**：会走路、上半身会跟着你的准星扭转、
还能开火。靶场和赛道图上各停了一台，都有画好的停机坪。

撑起造型的是剪影：带发光目镜的小脑袋深深陷在两块巨大的警示条纹肩甲之间、厚重平直的胸甲上印着人族骷髅翼徽、
短粗的手臂端着比躯干还长的双管炮、肩上的导弹发射巢、引擎背包上的排气管，以及宽大外撇的三趾脚掌。
其余全是细节堆料——成排铆钉、带镀铬活塞杆的液压缸、散热套筒、供弹带、散热鳍片。

它身上几乎没有一处是静态的，所以层级结构就是模型本身：

```
root ─ 骨盆
     ├ legs[2] ─ 髋关节 ─ 膝关节 ─ 踝关节 ─ 脚掌
     └ torso（绕 Y 扭转）
           └ arms（绕 X 俯仰）─ 双管炮组件
```

- **步态由行进距离驱动，而不是时间**，所以无论速度怎么变，腿永远和地面对得上，脚不会打滑。
  每条腿在前半个周期摆动、后半个周期蹬地；踝关节会把上面两个关节的角度减掉，保证脚掌始终贴平地面；
  身体每落一次脚下沉一次，每次落脚都会扬尘、发出闷响并震动镜头。
- **上半身扭转有角度上限**，所以身后的目标必须把腿转过去。
- **手臂主炮**是即时命中，走的是和步枪射击完全相同的射线、弹着和计分路径。它们会**汇聚到镜头看着的那一点**，
  而不是沿炮管轴线射——炮口在七米高、两米外，沿轴线打会远远飞过准星。
- **标枪导弹齐射**（鼠标右键）：肩部发射巢一次打出六发，弹道和爆炸处理与坦克炮弹完全一致。

### 载具

`src/world/Vehicles.ts` 用基本体搭出三台载具，每台的原点都在地面、车头朝 `+Z`。车身是**放样**出来的而不是
拼盒子：`loft()` 会给一串矩形截面蒙皮，所以楔形超跑车头、方正的吉普车身和坦克的倾斜首上装甲，
都出自同样这六十行代码。防滚架、保险杠和拖车钢缆则是沿路径扫掠的管体。

- **超跑**——放样楔形车身配独立玻璃座舱、碳纤维平底、前铲、导流片、侧裙和五片扩散器；鹅颈式尾翼；
  四出排气；贯穿式尾灯；百叶板下裸露的引擎舱；车门涂装；细杆后视镜；轮眉包边；
  以及带碳陶刹车盘和卡钳的五幅双辐轮毂。
- **吉普**——独立大梁、整体桥、钢板弹簧和减振器；七孔格栅配镀铬圈的圆形大灯；带绞盘的保险杠；
  扫掠管体防滚架配帆布顶棚和灯排；涉水喉；副油桶、工兵铲和斧头；尾门外挂备胎；侧踏板和轮眉；
  含座椅、仪表台、仪表盘和方向盘的内饰；以及钢轮上交错排布的粗大胎块。
- **主战坦克**——带倾斜首上装甲的车体，两侧各有一条侧裙和六片铰接裙板；带齿主动轮、诱导轮、
  七组扭杆悬挂负重轮、三个托带轮，以及沿行走机构路径生成的**约 120 片闭合履带板**；
  多面体炮塔配防盾、隔热套、抽烟装置和炮口制退器，车长指挥塔配观察镜和高射机枪、烟幕弹发射器、
  尾舱储物筐、拖车钢缆、备用履带板和天线。

三台都能开。`VehicleSystem` 负责持有它们：车壳被压成每种材质一个网格，而车轮（转向枢轴 + 滚转节点）
以及坦克的炮塔和火炮耳轴保持可动。停着的车持有一个碰撞盒，所以你会撞到它；正在驾驶的那台会把自己的碰撞盒清空——
它不能和自己相撞。

驾驶模型是街机式而非仿真：只有一个前进速度标量加一个朝向，没有解算器。轮式载具用自行车模型转向
（角速度 = 速度 · tan(转角) / 轴距），转向权限随速度衰减；坦克是差速转向，可以原地掉头。
三台都通过 `CollisionWorld.moveBox` 在同一套 AABB 碰撞世界里移动，台阶高度调得足够骑上路肩和车库门槛。
手感参数集中在 `src/vehicles/VehicleConfigs.ts`，一台车一个对象。

**圈速计时。** 赛道会给出一个 `LapCourse`——起终点线加三个检查点。只有**沿比赛方向**越过终点线、
且已经经过全部检查点，这一圈才算数；既不能在线上来回蹭圈，也不能抄内场近路。当前圈、上一圈和最快圈都显示在仪表上。

**坦克主炮。** 鼠标左键发射炮弹，有真实初速和重力下落，每一步都对世界做射线检测；命中后走的是和手雷完全相同的
爆炸路径——距离衰减、通视判定一个不少。装填有冷却，进度显示在仪表上。

### 模型测试场景

一个专门用来看模型的场景，完全按业界搭测试棚的做法来：三件展品放在会转的灯光展台上，
一面参考墙用来做对照，再加一块贴图检视板用来排查问题。

**六件展品**，每一件都专门打一个别的展品打不到的点。
- **Meridian GT-9 超跑。** 车身由十二个放样截面组成，每个截面都做了倒角和内收的车顶弧线；
  金属底漆之上叠一层独立的 `clearcoat` 清漆（自带极低粗糙度），再配一张稀疏的金属闪光法线贴图；
  带色的透射玻璃；用了 `anisotropy` 的碳纤维空力件；十辐涂装轮毂、打孔刹车盘和红色卡钳；
  以及钣金分缝线、轮眉外扩和轮胎侧壁字符。
- **Halden 三人沙发。** 程序化织物之上叠 `sheen` 绒感层，加拉扣、包边绳、明线走线，
  以及外八字的油蜡胡桃木腿和黄铜脚套。
- **Coldline CF-90 冰箱**，**可以打开**——走过去按 `E`。两扇门绕真实的合页线转开，
  冷冻抽屉往外滑出，内部灯光渐亮，里面有玻璃搁板、保鲜盒、门储物架和食品。外壳是各向异性的拉丝不锈钢。
- **陶盆龟背竹**——有机形态那一档。每片叶子就是一张 alpha 镂空的面片：那些裂口和孔洞**就是**模型本身，
  在这个预算下不可能做成几何体。用 `alphaTest` 而不是 `transparent`，叶子留在不透明批次里，
  不存在排序问题；three.js 会自己编译一份带贴图的深度材质变体，所以影子也是镂空的。
- **Halden No.5 打字机**，**可以打字**——按 `E`，一个键压下去、对应的字锤抬起来打到压纸卷上，
  **然后**字车才往左跳一格；打到行尾会自动回车。不过它真正考的是材质：
  掉漆的黑瓷漆下面露出裸钢，褶皱纹理的凹处积着灰——这是房间里其他任何一件展品都没有的东西。
  四十多个键帽共用一套几何体、一个材质、一张贴图，每个字母靠烘进 UV 的图集坐标来选。
- **水晶醒酒器 + 杯 + 酒液**——几乎没有几何体，纯粹是着色考核：
  `attenuationColor` 配 `attenuationDistance`（体积内的 Beer-Lambert 吸收，
  所以同一个参数下腹部是深琥珀、肩部是浅色），外加 `dispersion`。

**灯光棚。** 三盏 `RectAreaLight` 柔光箱分别作主光 / 补光 / 轮廓光，每盏都配了可见的灯板、边框和灯架；
一盏很弱的平行光只负责补回接触阴影（面光源不投影）；每个展台上方还有可选的射灯；
以及一面带弧形踢脚的无缝背景墙（cyclorama），地面和墙之间没有接缝。

**参考墙。** 金属度 0 和金属度 1 各一排九档粗糙度渐变球；一排六个球分别单独展示
`MeshPhysicalMaterial` 的一项特性——清漆、绒感、各向异性、虹彩、透射、高光染色；
十一级灰阶楔和八格色卡用来对曝光和白平衡；再加一个 1.8 米的人形比例参照。

**贴图检视板。** 碳纤维、拉丝钢、织物、胡桃木、掉漆瓷漆、陶土六套材质，各自把 albedo、法线和打包好的 ORM
以无光照的方式并排铺出来，旁边放一个套齐整套贴图的球。这块板就是实际排查贴图问题的地方：
某个粗糙度通道被画到过曝成全白、或者法线贴图被误标成了颜色贴图，在这里一眼就能看出来，
而在模型上根本看不出来。

### 场景与光照
没有用光线追踪，全部是常规前向渲染，只是把每一档都调到位，让空间看起来像个真实存在的地方：
- 太阳放在射击线**背后**，射手永远不会正对太阳；再加半球光、环境光，以及一盏代表混凝土地面反射的补光。
- 射击棚主要靠四盏强顶灯照明，高画质档再补一排；它们上方那几十条自发光灯管只是几何体，不是真光源。
- 灯具下方的叠加式光柱，以及在棚内缓缓飘动、完全由 GPU 驱动的浮尘。
- 密集的场景细节：屋架桁条、压型钢板屋面、桥架与线管、带玻璃的靶场控制室、墙面安全告示、
  摆着装备的射击台、弹壳桶、工具车、弹药箱、沙袋、水泥隔离墩、轮胎堆、托盘、油桶、
  锥筒、废弃车壳、外围铁丝网、树线和远处的山脊。

### UI
- DOM 实现的 HUD：准星开口由**真实散布锥角**换算为屏幕像素、弹药、射击模式、生命/体力、
  武器栏、命中提示、飘字伤害数字、事件日志、交互提示、受伤暗角，以及实时 FPS / draw call / 三角形计数。
- 狙击镜叠加层，带密位分划尺。
- 开始界面、暂停界面（设置项本地持久化：灵敏度、开镜灵敏度系数、FOV、视角摇晃、音量、画质档位、
  Y 轴反转、开镜/蹲下切换模式、准星、伤害数字、FPS 显示），以及死亡界面。
- 三档画质预设，联动像素比、阴影、Bloom、SMAA、粒子数量与动态光源。

## 如何扩展

### 新增一把武器

1. 在 `src/weapons/WeaponTypes.ts` 的 `WeaponId` 中加入新 id。
2. 在 `src/weapons/WeaponConfigs.ts` 中新增一份 `WeaponConfig`，并注册到 `WEAPON_CONFIGS` / `WEAPON_ORDER`。
   所有系统读取的数值都集中在这一个对象里。
3. 在 `src/weapons/WeaponMeshes.ts` 中新增一个构建函数，返回带有具名锚点的 `WeaponModel`
   （`muzzle`、`sight`、`ejectPort`、`gripAnchor`、`foreAnchor`，可选 `magazine`、`slide`、`charging`、`scopeLens`）。

其他地方都不需要改动：手部模型会根据模型包围盒和 `sight` 锚点自动推导出腰射距离与开镜姿态，
第三人称角色会自动把双手 IK 到 `gripAnchor` / `foreAnchor` 上，HUD、展示台和数字键也都是读 `WEAPON_ORDER` 的。

### 新增一种投掷物

在 `src/weapons/ThrowableConfigs.ts` 的 `ThrowableId` 中加 id、在 `THROWABLE_CONFIGS` 中加配置、
在 `buildThrowable()` 中补上模型，最后在 `Game.onDetonate()` 里处理新的爆炸效果即可。
拔销/投掷状态机、物理和 HUD 都与具体效果无关。

### 替换成真实美术资源

`buildWeaponModel()` 是唯一创建枪械几何体的地方。把它换成 `GLTFLoader` 调用，
并把对应节点标记为上述锚点即可——代码库其余部分只和锚点打交道。
`CharacterModel` 同理：用蒙皮网格替换基本体骨架，驱动同样的关节即可。

### 新增靶标

在 `ShootingRange.buildTargets()` 中调用 `new RangeTarget({ kind, position, ... })`。
要新增一种 `TargetKind`，写一个 `buildX()` 方法，用 `tag(mesh, zone, surface)` 标记网格，
再在 `registerHit()` / `update()` 中补上对应分支。

### 修改关卡 / 新增地图

关卡继承 `LevelBuilder`（`src/world/LevelBuilder.ts`）并实现 `build(): LevelBuildResult`。
`box()` 辅助函数一次调用即可完成"添加网格 + 注册碰撞 AABB + 加入射击射线检测列表"三件事，
所以新加的几何体天生就是接好线的。表面通过 `userData.surface` 标记，它同时驱动弹着特效、弹着音效和脚步声。

要新增一张地图：给 `LevelId` 加一个 id、往 `LEVELS` 里加一条，写好 builder，再在 `Game.buildLevel()`
中加一个分支。其余部分——菜单里的地图选择、`M` 键、切换时的拆除与重建——都是从 `LEVELS` 推导出来的。

做大型室外关卡前有两件事值得知道：

- **尽量合批。** 静态几何体走 `box`/`prop`/`propObject`，在 `build()` 末尾调一次 `flushBatch()`。
  赛道图约 800 个基本体，连同画面上其他所有东西一共约 550 个 draw call。
- **要盯的是碰撞盒数量，不是三角面数。** 碰撞是纯 AABB 且线性遍历，所以一段长长的斜向护栏绝不能变成
  一个被撑得巨大的包围盒。做法可以参考 `RaceTrack.barrierColliders()`：沿折线走一遍，
  每一段朝向基本不变的连续区间只生成一个碰撞盒。

### 新增一台载具

1. 在 `src/world/Vehicles.ts` 中给 `VehicleId` 加一个 id，写一个返回 `VehicleBuildResult` 的 builder。
   建模时车头朝 `+Z`、原点放在地面；`loft()`、`tube()`、`axle()`、`bothSides()` 和 `buildWheel()`
   基本覆盖了造一台车所需要的一切。车轮用 `mountWheel()` 挂上去，它们才会带着转向枢轴和滚转节点进到 `parts.wheels`。
2. 在 `src/vehicles/VehicleConfigs.ts` 里加一份 `VehicleConfig`。要能开炮就加上 `cannon` 块。
3. 把出生点加进关卡的 `vehicleSpawns`。

其余部分不用动：上下车、仪表、追尾镜头和圈速计时都是从 config 和 parts 里读的。

建模时有两件事一定要做对：

- **车壳绕序必须朝外。** `loft()` 之所以是"先走完自己这一段截面再前进"，就是为了这个——想当然的那种顺序
  会让四个侧面法线全部朝内，背面剔除随即把朝向你的那一面剔掉，于是你会直接看穿车壳、看到远侧的内壁。
  而端盖用的是另一套绕序、始终是对的，这让问题极难被发现。
- **敞篷必须是真的敞篷。** 车斗要做成一个实心体、它的顶面就是驾驶舱地板，两侧板再作为独立件加回去。
  如果只是靠"顶面被剔除"看起来是敞篷，那么绕序一修正，内饰立刻就被封死在里面了。

### 调整手感

- 移动：`src/player/Player.ts` 中的 `DEFAULT_PLAYER_CONFIG`。
- 摄像机：`src/player/CameraController.ts` 顶部的常量。
- 手部模型姿态：`src/player/ViewModel.ts` 中的 `HIP_POSITION`、`SPRINT_ROTATION`、`STOCK_CLEARANCE`。
- 渲染：`src/core/RenderPipeline.ts` 中的 `QUALITY_PRESETS`。

## 实现要点

**手部模型渲染。** 第一人称武器位于独立的 `THREE.Scene`，有自己的摄像机与灯光，
由自定义的 `ViewModelPass` 叠加到世界之上——它先绑定渲染目标**再**清空深度。
（`RenderPass.clearDepth` 是在绑定目标之前清深度的，当它不是第一个 pass 时并不可靠。）

**开镜对齐是自动的。** 装备武器时，手部模型在模型处于单位变换的状态下读取 `sight` 锚点的位置，
然后解算出把该点精确放到屏幕中心轴上的姿态。新的枪械美术不需要任何手调的开镜偏移。
同一份包围盒计算还会推导出枪需要前移多少，保证枪托永远不会越过近裁剪面。

**瞄准权威。** `CameraController.aimYaw/aimPitch`（玩家视角 + 后坐力）才是射线追踪使用的方向。
摇晃、震动、倾斜和横移滚转都在之后叠加，纯粹是表现层。第三人称下，摄像机先射线求出瞄准点，
再从角色枪口朝该点追踪，这样准星始终诚实，同时又不会让你从掩体后面"隔墙开枪"。

**帧内顺序。** 输入 → 角色物理 → 摄像机 → 武器 → 手部模型/角色 → 特效 → HUD。
摄像机在武器**之前**更新，这样本帧开的枪用的就是本帧的瞄准方向，没有一帧的输入延迟。

**静态合批。** 关卡是用几百个小基本体拼出来的，然后在第一帧之前由 `StaticBatcher` 按材质合并成二十来个网格。
表面标签是合批 key 的一部分，所以合并后的网格依然能报出正确的材质（弹着特效和脚步声都依赖它）；
而射线只检测正面，子弹打进实心盒子后不会在穿出时再命中一次，因此穿透逻辑不受影响。
靶标的静态支架和展示台上的枪械也走同一条路径。没有这套合批，上面那些场景细节会带来两千多个 draw call。

**深度精度。** `EffectComposer` 默认的渲染目标只分配 **16 位** 深度缓冲，在 2000 米远裁剪面下根本不够用——
赛道路面、缓冲区和地面三层几乎共面，几十米开外就开始 z-fighting。因此这里给 composer 传了一个
`stencilBuffer: true` 的渲染目标，让它改用 `DEPTH24_STENCIL8`。做大面积、平坦、分层的室外几何之前值得先知道这件事。

**天空与 Bloom。** `Sky` 输出的是物理辐亮度，屏幕上半部分基本都远超 1.0。色调映射本身扛得住，
但 Bloom 是在它**之前**跑的，于是未经处理的天空球等于给 Bloom 递上一个全屏过亮源，结果就是整个画面蒙上一层白雾。
`LevelBuilder` 会往天空 shader 里插一条 Reinhard 压缩曲线，其渐近线压在 Bloom 阈值之下：
渐变保留下来，任何一个天空像素都不会进入高通，而枪口火焰和自发光物件完全不受影响。

**太阳的摆放。** 平行光的方向是 `position - target`，所以当阴影目标在一百米外、而太阳却按世界坐标固定摆放时，
太阳的实际高度角会被悄悄压平。`buildSkyAndSun` 是**相对目标**放置太阳的——这样关卡要一个 46 度的太阳，
拿到的就真是 46 度。

**PBR 贴图的生成。** `PbrSurface` 在 canvas 上生成金属度-粗糙度工作流的整套贴图：sRGB 的 albedo、
由高度场用中心差分推出的切线空间法线，以及**把环境光遮蔽、粗糙度、金属度分别打包进同一张贴图 R、G、B 通道**
的 ORM。这个打包方式就是 glTF 的约定，three.js 读的正是这几个通道
（`aomap_fragment` 取 `.r`，`roughnessmap_fragment` 取 `.g`，`metalnessmap_fragment` 取 `.b`），
所以一次采样、一次上传就顶三张贴图。贴图是**乘**到材质标量上的，所以 `applySurface` 会把
`roughness = metalness = 1`——保持默认值会让每一种金属的金属度都被悄悄砍掉一半。

三个很容易做错、又很难看出来的地方：

- **法线强度不是凭感觉调的旋钮。** 它是"每个纹素上的高度斜率"，而中心差分本身已经跨了两个纹素。
  填 10 就等于要求织物的每一根丝上都出现 83 度的斜面——碳纤维会渲染成一颗迪斯科球。
  要对着真实特征的尺寸去标定。
- **半透明笔触叠加是单向棘轮。** 用很多道低透明度的白色划痕去画一个通道，无论底色多深都会被推到全白；
  拉丝钢这么画出来粗糙度是 0.9。要让一半划痕是暗的，均值才会停在你设定的位置。
- **数据贴图不是颜色贴图。** 法线和 ORM 在材质上必须是线性的。检视板刻意反着来、把预览标成 sRGB，
  因为那里的目标是"显示字节本身"：着色器解码、输出 pass 再编码回去，纹素刚好原样往返。

**基于图像的光照（IBL）。** `PMREMGenerator.fromScene(new RoomEnvironment())` 会把一个室内场景
预过滤成辐射度贴图，并生成对应的 mip 链，材质才能按自己的粗糙度采到正确的模糊等级。
清漆、绒感、各向异性、虹彩、透射全都是反射类效果——没有环境贴图，它们就没有东西可反射，
无论贴图做得多好都会塌成平板着色。`RenderPipeline.setEnvironment` 为每张关卡各建一份，强度由关卡自己指定。
要把这个强度当成一盏灯来看：设成 1.0 时，哪怕把房间里所有灯都关掉，冰箱内胆的白色内衬照样会冲过 Bloom 阈值。

**明亮房间里的曝光纪律。** 后处理跑在色调映射之前，所以**任何**漫反射面只要辐射度越过 Bloom 的 1.0 高通，
就会给整个画面糊上一层奶白——和上面天空穹顶那条是同一个失效模式，只不过这次来自一面白墙。
测试棚里大面积的浅色表面特别多，所以背景墙刷的是中灰、灯光强度是量出来的而不是拍脑袋定的、灯板也走色调映射。
越过那个点之后再把灯**调亮**，画面不会更亮，只会更奶。

**面光源的朝向是反的。** `Object3D.lookAt` 对灯光和摄像机是把局部 **-Z** 对准目标，
对其它物体则是局部 **+Z**；而 `RectAreaLight` 恰好也是沿着这个 -Z 发光。
于是把灯的四元数直接抄到代表它的那块平板上，会让发光面背对被摄体，还被自己的边框挡住。
另外 `RectAreaLight` 需要先调用 `RectAreaLightUniformsLib.init()`，只照亮 Standard / Physical 材质，
而且完全不投影。

**材质分层。** 一件用旧的东西不是"一种材质 + 一张脏贴图"，而是一个叠层：钢、盖在大部分表面上的瓷漆、
以及沉在瓷漆没盖住的地方的积灰。`layeredSurface` 用一张遮罩把两套完整材质混起来，而且**每个通道都要混**——
一处掉漆必须同时改变颜色、粗糙度和金属度，只改第一个得到的是"一张掉漆的贴花"而不是掉漆。
真实的边缘磨损跟着模型曲率走、是从高模烘出来的；平铺贴图根本不知道模型的棱在哪，
所以 `chipMask` 走的是贴图美术的路子：撒一堆边缘参差的碎片。边缘必须是硬的，软边只会读成一块污渍。

两条标定经验，都是踩出来的：一百个小碎片会读成花岗岩，而只把数量砍下去又会让磨损彻底看不见——
**尺寸**才是"磨损"和"噪点"的分界线。以及，检视板就是用来看这个的：
在 ORM 面板上，一处掉漆是 G、B 通道从"粗糙介电质"跳到"光滑金属"的一个洞；
只看 albedo 面板的话，它就只是一个浅色斑点，赝品长得一模一样。

**体积吸收，以及教科书模型为什么渲不出来。** 体积的颜色来自 `attenuationColor` 和 `attenuationDistance`——
Beer-Lambert 定律，所以颜色随光程加深，一个固定参数就能给出浅色的边缘和浓郁的中心。
参考墙上那颗 ABSORPTION 球就是证明它工作正常的对照组。

而做醒酒器最直觉的做法，是把 IOR 1.36 的液体壳套进 IOR 1.55 的玻璃壳里。
这个做法渲出来是**什么都没有**：three.js 的透射折射的是一张只含**不透明**物体的背景图，
所以"透射物体套在透射物体里面"不在任何人的背景里，直接隐形——
实测：酒液渲出来是中性灰，而同样的吸收参数放在一颗独立的球上就是琥珀色。
所以每个容器都改成沿液面切开的两块实体：下面一块带着威士忌的吸收，上面一块是中空的水晶壳。
眼睛收到的本来也就是这个——玻璃、酒、玻璃合起来读成一整块琥珀色的体积——
而且它能在"只折射一次"的渲染器里成立。剩下的限制是真实存在的：没有任何东西会被折射两次，
所以隔着醒酒器看后面的杯子，那个杯子不会被弯折。

**会折射的展品会把周围的环境吃进去。** 测试棚里其他展台边缘都有一圈发光的青色灯带。
放在水晶下面时，它把酒液渲成了绿色——实测采样值 (111,183,111)——
因为饱和的青色透过琥珀色吸收之后**就是**绿色。渲染器没错，错的是布景；
那个展台干脆不放灯带，真实的摄影棚在玻璃器皿附近也不会摆有色实用光源。

**性能。** 靶场约 550–700 个 draw call、约 19 万三角形；赛道图在维修区、三台载具和半条赛道同时入镜时
约 700–900 个 draw call、约 60 万三角形；模型测试场景约 700–1300 个 draw call、约 34 万三角形，
开销主要在材质而不是几何体上。在任何独显或较新的核显上都很轻松。
光照是刻意克制的——前向渲染中每一盏灯都要在每个受光像素上算一遍，所以射击棚内是用四盏强灯而不是每个灯具一盏，
车库则是每个车位两盏。需要更多余量就调低画质档位：会关闭 Bloom、SMAA、阴影、第二排顶灯、泛光灯塔和大气效果，
并把粒子数量减半。
